# 电脑主流程与香橙派旁路边缘分析计划

状态：2026-11-17 用户确认的最新分工，尚未实现。本计划替代此前“香橙派作为 Arduino 硬件网关”的实施方向；历史代码分析与实际接线核实仍然有效。

## 分工与约束

- 电脑负责 Arduino USB 数据读取、Flask、数据库、网页、摄像头接入和视觉识别。网页控制能力以引脚核查和固件可行性结果为准，不能认为已经实现。
- 两块 UNO 保留现有模块接线和本地控制。允许改固件，但先查明实际引脚占用、现有功能及可恢复版本。
- Arduino USB 继续接电脑，本方案不要求移接香橙派。
- 摄像头为 ESP32-CAM，拟通过网络向电脑提供视频，USB 不等同于 UVC 视频输入；当前配置和性能待验证。
- 香橙派通过网络接收电脑发送的数据副本，完成旁路分析和本地记录。它不处于硬件控制、视频预览、正式识别和业务请求的必经路径。
- 香橙派离线、处理慢、网络不通或返回异常，都不能阻塞主流程。第一版分析结果只作提醒，不直接驱动执行器或触发开门。

```text
Arduino USB -> 电脑采集 -> Flask / 数据库 / 页面
                   |
                   +-> 有界异步发送 -> 香橙派分析与本地记录
                                          |
                                          +-> 分析结果 -> 页面边缘分析区域

ESP32-CAM -> 网络视频 -> 电脑预览与独立抽帧识别
Arduino 的本地键盘、语音和自动控制仍按自身固件运行
```

## 第一版边缘任务

| 工作 | 输入与行为 | 输出 |
| --- | --- | --- |
| 数据质量检查 | 按设备检查更新间隔、必需字段、有效性及配置的数值范围 | 数据中断、字段缺失、异常值提醒 |
| 规则与事件分析 | 比较雨滴/土壤状态变化，连续干燥提醒；温度数据接入后再增加温度规则 | 带证据和来源序号的事件 |
| 本地记录与统计 | 保存收到的数据副本，统计采集间隔和干湿变化 | 历史记录、分析时间和统计摘要 |

土壤/雨滴原始值和相对百分比并非已校准物理含水率。设备报告 DRY 不等于现场已验证干燥。数据未知、无效、超时与正常状态必须分开。

板端视觉推理仅作为后续独立试验，不列入第一版验收。是否使用板端 AI 加速，取决于实际板型、系统、运行环境和模型兼容性，不预先承诺性能。

## 数据与接口草案

以下字段和接口职责是设计草案，尚无对应服务部署。先明确数据含义，再确定实际 URL 和实现。

电脑发送的数据包含：协议版本、稳定设备标识、采集进程启动标识、递增序号、电脑接收时间、有效字段、原始状态和质量标记。当前没有 Arduino 原始采集时间时明确使用电脑接收时间，不冒充传感器采样时间。端口名 COM9/COM10 只用于本机设备对应，不能作为永久设备身份。

香橙派补充接收时间并输出：节点标识、启动标识、结果/事件 ID、来源设备与序号、规则版本、分析时间、结果、原因和有效期。需保留来源，避免迟到结果覆盖新状态。

电脑到香橙派的数据入口与香橙派到电脑的结果入口独立于现有控制接口，建议采用局域网 HTTP JSON。节点心跳与数据心跳分别记录；身份验证配置保留本地，不提交凭据。仅转发任务必要的传感器字段，第一版不发送人脸图库或连续视频。

## 故障隔离

- 主流程先完成自己的数据处理，旁路发送采用独立工作线程/进程和有界缓冲，不在网页请求或串口读取循环里同步等待香橙派。
- 设置连接/请求超时、有限重试和退避；队列满时丢弃或合并旧样本并记录计数，不能无限占用内存。
- 高频当前状态优先保留最新值。事件若需要可靠交付，另定义有界持久化队列和去重语义，不能承诺数据副本零丢失。
- 用启动标识和序号处理重复/乱序，重连后发送最新状态，禁止补发历史控制命令。
- 香橙派本地记录有容量/保留期限，满盘时报告错误，不能影响电脑。
- 页面显示边缘节点在线/离线、最近收到数据时间、最近分析时间和结果过期状态。旧结果不能一直显示为当前结论。
- 香橙派可以在电脑停止发送后提示中断并保存已有记录，但不能继续获取新传感器数据，不能称为独立硬件接管或完整备份。

## 实施阶段

1. **电脑端硬件摸底**：继续 Issue #4，核实两板端口、引脚占用和不改线的功能边界。参考 PR #5 实测记录，不能假定参考固件与板上程序一致。
2. **旁路协议与模拟联调**：准备样本数据和预期结果，验证有效/无效/超时、重复和乱序处理，不依赖 Arduino 完整改造。
3. **香橙派基础服务**：核实系统、网络及运行环境，部署数据质量、规则与本地记录服务。只测试指定节点的连通性，不更改校园网配置。
4. **真实数据与页面接入**：先接已验证的雨滴/土壤数据，再扩展其他字段；页面独立显示边缘分析。
5. **故障验收**：分别停止边缘服务、断开网络、延迟响应、发送错误响应，确认主流程不中断且资源使用有界。

摄像头配置和流畅预览独立推进，不等待边缘分析完成。

## 验收标准

- 能从指定设备接收真实数据，追溯来源序号，产生可解释的状态变化事件。
- 已配置的超时能正确提示，数据恢复后能解除；重复事件不会无限重复显示。
- 香橙派离线或慢响应时，电脑串口采集、页面与视频继续运行。用相同条件对比启用/停用旁路时的采集间隔、响应耗时和视频表现，记录实际数据，不只凭主观判断。
- 缓冲、重试和本地存储容量有明确限制，长时间离线不会持续增长。
- 若硬件控制尚未实现，则不能声称已通过控制链路隔离验收，待该能力实现后补测。
- 本阶段不改模块接线，不迁移 Arduino USB 主机，不以停用语音/键盘换取接口可用性。
