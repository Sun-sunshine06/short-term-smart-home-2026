# 双 UNO R3 USB 控制与 D3 语音版

版本：USB_ASR_D3_V1，2026-11-17。

本包用于先验证硬件，再接入软件组的 GUI 和人脸识别系统。包含两块 UNO 的完整程序、配套头文件、编译固件和测试记录。USB 命令入口已经实现；本包不包含软件组后端迁移或人脸识别算法。

## 1. 只移动新板上的一根信号线

断开 USB、电池及其他外接供电后，将 ASRPRO TX（原资料标记 PA_2 / Serial1 TX）从新扩展板 D0 移到新扩展板空闲的 D3。ASRPRO 那一端不动。新板 D0/D1 不接 ASRPRO 或其他外部发送端。

注意是新扩展板 D3；旧主控板 D3 仍然连接门舵机。ASRPRO 和两板原来的供电及共地连接保留。若实物新板 D3 已接其他模块，暂停改线并核对，不能并接。

其他信号线不动：

| 新扩展板引脚 | 连接 |
| --- | --- |
| D2 | 触摸模块 OUT |
| D3 | ASRPRO TX，9600 波特率、8N1，只接收 |
| D8 / D9 | 超声波 TRIG / ECHO |
| D10 | 旧主控板 D5 |
| D13 | 板载状态 LED |
| A0 / A1 | 雨水 AO / 土壤 AO |
| USB | 电脑或香橙派，115200 波特率、8N1 |

旧主控板所有接线保持原样。两板间的通信仍是新板 D10 → 旧板 D5，仍需共地。

后续 GUI 接入时，将新板 USB 接到运行桥接程序的电脑或香橙派，二选一。先验证硬件时可以直接使用 Arduino IDE 的串口监视器。不需要额外 USB 转 TTL 模块。不能仅靠改线使用旧版新板程序，必须烧录本包的新板代码。

## 2. 两块板分别打开哪个程序

- 旧主控板：`OldBoard_Main/OldBoard_Main.ino`，同目录保留 `HomeLink.h`。
- 新扩展板：`NewBoard_Expansion/NewBoard_Expansion.ino`，同目录保留 `HomeLink.h`、`AsrD3Rx.h`、`CommandInput.h`。

请完整解压本包，不要只复制 `.ino`。板型选择 Arduino Uno（UNO R3 / ATmega328P / 16 MHz），不要选择 Uno R4。普通 Arduino IDE 使用者打开 `.ino` 编译上传即可，不必使用 `compiled/` 的 HEX。

旧板依赖：U8g2、DHT sensor library by Adafruit、Adafruit Unified Sensor、Adafruit NeoPixel、Servo。新板不需要第三方库，也不要额外加入 SoftwareSerial。

本包旧板保留原 V2 控制逻辑，只更新版本注释，仍与原 V2 协议兼容。为保证现场版本明确，建议两块板均上传本包对应文件。不能与最早的脉冲计数协议固件混用。

## 3. 烧录顺序

1. 完成断电改线，确认新板 D0 已空出。
2. 用 USB 连接旧板，选择实际对应端口，打开旧板程序并上传。上传时不要按键盘，旧板 D0/D1 仍连着键盘。
3. 用 USB 连接新板，重新选择对应端口，打开新板程序并上传。不得把两个程序烧到同一块板。
4. 两板均正常供电后，等待约 2 秒再测试。
5. 打开新板串口监视器，设置 115200 波特率、发送结尾选择“换行”。打开串口通常会使新板复位，等待启动提示及约 2 秒后再发命令。

新板启动提示：`USB_ASR_D3_V1_READY,USB:115200,ASR:9600`。

每次只让一个程序占用新板串口。软件桥接运行前关闭串口监视器。串口打开或重新上电会清空新板待发队列，不要假定之前的命令仍会执行。

## 4. 先用串口监视器验证

每次发送一条命令，并观察实际动作；连续操作建议间隔约 1 秒。

| 命令 | 作用 |
| --- | --- |
| PING | 返回 `PONG,USB_ASR_D3_V1`，检查 USB 通信 |
| LO / LC | 开灯 / 关灯，并切换到手动照明模式 |
| FO / FC | 开风扇 / 关风扇，并切换到手动风扇模式 |
| DO / DC | 开门 / 关门，开门约 4 秒后自动关闭 |
| BELL | 响门铃，不开门 |
| FA / LA | 恢复风扇 / 照明自动模式 |
| AUTO | 两者都恢复自动模式 |
| FACE_OPEN | 与开门动作相同，但接受一次后 10 秒内再次收到会被抑制 |

USB 命令必须带换行、回车或分号。大小写均可。输入太长、包含异常字符或不完整输入超过 1 秒都会丢弃，不执行残缺命令。超时后先发送一次换行，再发送新的完整命令。

ASRPRO 的语音程序不需要更改：原 DO/DC/FO/FC/LO/LC/BELL 等文本短命令仍可使用。语音输入仍支持无换行、末尾空闲至少 40 ms 的旧格式。USB 和 ASR 使用独立解析缓冲，互不拼接。

`FACE_OPEN` 只提供命令入口，不会自行识别人脸，也不验证命令发送者的身份。后续软件只应在授权人脸通过时发送它。10 秒冷却从入队时计算，冷却中的命令直接丢弃；新板复位会清除冷却。为了避免同一人一直站在镜头前导致每 10 秒重复开门，软件组仍应只在新一次授权事件发生时发送，而不是每帧发送。

## 5. 原功能复测顺序

1. 按键逐行检查，尤其 7/8/9；输入 `1234#` 开门，约 4 秒自动关门，`*` 清空。
2. 输错密码，确认报警时按键仍能响应，并可处理开门命令。
3. 用原语音词条测试开关门、灯、风扇。串口应出现 `ASR_CMD:...`。如果 USB 正常而语音无反应，先检查 ASR TX 是否确实到了新板 D3、共地和 ASR 波特率。
4. 用 USB 测试同样的动作，再交替发送语音和 USB 指令。
5. 语音或 USB 关闭风扇后按键 A，恢复自动温控；关闭灯后按 B，恢复自动照明；D 同时恢复两者自动。
6. 温度 >=28°C 开风扇，<=27°C 关，中间保持原状态。DHT11 每 2 秒采集，失败显示 ERR。
7. 触摸只响门铃，长按只触发一次；超声波只报告距离和靠近状态，不自动开门。
8. 改变雨水、土壤状态，核对 OLED 显示；停止新板通信后，旧板对应状态约 15 秒后变为 `--`。
9. 测试 FACE_OPEN：第一次开门，4 秒后自动关；10 秒内再次发送不延长开门、不排队补开。

手动开关灯/风扇后，自动传感器逻辑不会立即覆盖该手动选择。需通过 A/B/D 或 FA/LA/AUTO 恢复自动。

## 6. 回应含义和能力范围

- `USB_CMD:LO,ID:5,QUEUED`：新板已接受命令并入队，不是旧板执行确认。
- `LINK_TX:ID:5,SEQ:...,SENT_NO_ACK`：新板已完成发送，没有收到或等待旧板确认。用户命令有同序号重复帧，旧板去重。
- `USB_BUSY:...`：命令队列满，该命令未接收。不能无限快速发送控制命令。
- `USB_UNKNOWN:...`：未知、过长或损坏命令，未执行。
- `USB_CMD:FACE_OPEN,COOLDOWN`：人脸开门命令处于冷却期，未入队。
- `ASR_RX_ERROR,COMMAND_DISCARDED`：D3 接收检测到停止位、缓冲区溢出或采样超时问题，丢弃相关输入，避免执行损坏命令。

日志采用有界缓冲；过载时允许丢日志，不阻塞控制。因此未看到某条日志也不表示动作一定未发生。当前 USB 文本协议适合本地联调，后续若要求请求编号、可靠应答或自动重试，需增加完整协议，不能把日志当成硬件 ACK。

本次只提供单向控制：没有增加旧板到新板的返回线。旧板的温湿度、实际执行状态不能经这条单向链路回传 GUI。新板 USB 可以报告它自己的雨水、土壤、超声波读数。OLED 的门状态仍是控制状态，不是门位置传感器反馈。灯环保留固定亮度 35，不支持任意亮度百分比设置。

## 7. 实现与验证说明

新板 D3 使用 INT1 和 Timer1 比较中断接收 9600 8N1。每次定时中断只采一个位，没有用标准 SoftwareSerial 占用超声波的 PCINT0 中断。新板 D9 超声波仍用 PCINT0，Timer0 仍负责 millis/micros。

Timer1 仅在新板被语音接收占用；因此不要在新板额外使用 Servo、Timer1 或 D9/D10 的 PWM。旧板是另一颗 MCU，其 Servo 和风扇 PWM 不受此占用影响。

实际 AVR 编译与主机模拟结果见 `verification/验证结果.md`。主机模拟不等于上板验收；尚未测量你们实物上的 D3 信号、电源、并发中断时序、舵机机械角度或传感器极性。若实机语音持续报错，需要结合实际模块信号进一步调试。
